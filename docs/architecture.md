# 코드 구조

[처음으로](../README.md) · [설정 안내](configuration.md) · [운영·문제 해결](operations.md)

수집·계획·표현·전송을 분리해 소스가 늘어나도 실행 흐름과 출력 규칙을 각각 확인할 수 있게 구성합니다. 기본 진입점은 계속 `python main.py`입니다.

| 모듈 | 담당하는 일 |
| :--- | :--- |
| [`main.py`](../main.py) | CLI 진입점과 기존 호출 호환 |
| [`briefing/cli.py`](../briefing/cli.py) | 실행 옵션, 데모·실제 미리보기·설정 진단 |
| [`briefing/pipeline.py`](../briefing/pipeline.py) | 선택한 소스 수집과 실행 진단 |
| [`briefing/planning.py`](../briefing/planning.py) | 일정 충돌·남은 빈 시간과 오늘의 계획 계산 |
| [`briefing/rendering.py`](../briefing/rendering.py) | 핵심 요약·각 섹션·플래너를 읽기 쉬운 출력으로 구성 |
| [`briefing/export.py`](../briefing/export.py) | 같은 브리핑을 텍스트·Markdown·JSON·HTML로 내보내기 |
| [`briefing/demo.py`](../briefing/demo.py) | 외부 요청 없이 쓸 수 있는 공개 가상 데이터 |
| [`sources/`](../sources/) | 캘린더·과제·날씨·뉴스 등 수집과 유효성/최신성 확인 |
| [`discord_sender.py`](../discord_sender.py) | embed 구성, Discord 제한에 맞춘 분할과 전송 재시도 |
| [`settings.py`](../settings.py) | 환경 변수의 기본값과 개인 설정 |

## 실행 흐름

1. **설정과 실행 모드 확인:** 표시 섹션, 분량, 데모·미리보기·전송 모드를 정합니다.
2. **데이터 수집:** 선택한 소스를 병렬 조회합니다. 데모는 네트워크 대신 고정 가상 데이터를 사용합니다.
3. **하루 계획 계산:** 조회한 일정과 과제로 겹침·마감·남은 시간을 정리합니다. 소스가 불완전하면 그 상태를 함께 표시합니다.
4. **출력 구성:** 핵심 정보를 앞에 두고 세부 섹션을 이어 붙입니다. 시간과 데이터 출처를 보존합니다.
5. **미리보기 또는 전송:** 미리보기는 결과를 표준 출력이나 파일로 보내고, 운영 모드는 Discord 제한에 맞춰 나눠 전송합니다.
6. **상태 보존:** 읽기 전용 모드는 상태를 바꾸지 않습니다. 운영 워크플로는 전송 성공 후 공개 상태 파일을 Git에 저장합니다.

## 플래너의 계산 범위

빈 시간은 **현재 시각 이후, 09:00–23:00 중 30분 이상인 구간**입니다. 일정이 정상 조회된 경우에만 계산합니다. 부분 실패·미연결 상태에서는 빈 시간을 확정하지 않습니다. 이동·준비 시간은 포함하지 않으므로 실제 계획에서 따로 고려합니다.

겹침은 아직 끝나지 않은 시간 지정 일정 사이에서 찾습니다. `TRANSP:TRANSPARENT`로 표시한 일정은 시간을 차지하지 않는 알림으로 취급합니다. 시간을 차지하는 종일 일정은 하루의 빈 시간을 막습니다. 가까운 마감은 오늘부터 7일 이내, 연체는 별도로 분류합니다.

## 새 소스를 추가할 때

`sources/`에 수집 함수를 만들고 `briefing/pipeline.py`의 수집 목록과 `settings.py`의 섹션 설정을 연결합니다. `briefing/rendering.py`에서 데이터를 표현하고 [데이터 소스](sources.md)에 출처·허용 경과시간·실패 표시를 기록합니다.

출력 함수는 데이터를 다시 조회하지 않아야 데모와 실제 브리핑에서 같은 형식을 검증할 수 있습니다. 공급자 문자열이나 파싱 예외를 그대로 출력하면 비공개 URL이 섞일 수 있으므로 공개 로그에는 필요한 오류 종류와 소스 이름을 남깁니다.

새 데이터는 정상값뿐 아니라 **빈 결과·오래된 값·형식 변경·부분 실패**를 구분할 수 있어야 합니다. 테스트는 공급자 응답을 대체해 해당 경계의 결과를 확인하고, 외부 서비스와 실제 전송이 필요한 확인은 별도로 기록합니다.
